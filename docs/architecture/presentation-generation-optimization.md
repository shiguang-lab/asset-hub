# 演示文档生成链路优化方案

## 现状判断

当前链路已经是 HTML-first：规划 → foundation → 逐页生成 → 确定性 instrument → Chromium fit/audit → 逐页修复 → 发布。历史失败主要集中在三类：

1. 规划容量不可行（单页条目数超过画布可承载范围）。
2. 生成样式选择器或语义标记没有命中真实 DOM，修复循环看不到效果。
3. 浏览器检测只扫描带 `data-sg-id` 的节点，导致来源行、SVG 标签和自定义包装器漏检。

## 业内做法对照

| 方案 | 核心机制 | 对本系统的启示 |
| --- | --- | --- |
| Gamma | 先组织内容，再用可变 card/section 布局动态适配；支持大纲与逐页编辑 | 规划阶段必须有容量预算；页面可变但需保留稳定锚点 |
| Beautiful.ai | Smart Slides 自动对齐、调整间距和尺寸，按数据/对比/时间线选择专用版式 | 把“布局原语”交给平台测量与约束，不让模型靠微调像素收敛 |
| Tome | 先生成 outline，再为每页提供多个版式候选，用户可选择后生成 | 生成前先锁定叙事和视觉方向，避免整篇页面同构 |

## 落地设计

### 生成层

- 规划器输出 audience、core message、叙事、视觉方向、design system 和每页容量预算。
- 单页正文 ≥26px、脚注/来源 ≥20px；并列条目 >8 时改紧凑矩阵或表格。
- foundation 只提供 token、网格和视觉语法；页面只返回一个 section，样式必须用 `#page-N` 限定。
- 动画仅允许 CSS，图表通过 `data-sg-chart` 交给运行时渲染，避免“提示词允许 JS、校验又禁止 script”的矛盾。

### 检测层

- 页面级检测：固定 1920×1080 舞台、滚动高度/宽度、越界最深元素。
- 元素级检测：扫描所有可见语义节点；除了 `data-sg-id`，还纳入无 ID 的文本叶节点、图片、SVG、Canvas、表格和图表节点。
- 关系级检测：跨容器检查大面积重叠，忽略 decoration/background 和包含关系，限制报告数量避免噪声淹没修复模型。
- 字号检测：按直接文本节点和语义角色计算有效字号；source/footer/caption/decoration 豁免，table/chart/metric 使用密集阈值。

### 修复层

- 逐页修复、逐页复检；通过页锁定，失败页留在队头继续尝试。
- 相同测量指纹重复时注入“无生效”诊断，要求先修选择器/继承问题，再改变布局。
- 修复预算耗尽时只对停靠页启用 ≥0.90 的降级缩放，并把残留问题降为 warning；正常页面不以缩放掩盖过载。

### 运营指标

- 生成成功率、平均修复次数、每页首次通过率。
- `RENDER_ELEMENT_OUTSIDE_STAGE`、`RENDER_TEXT_CLIPPED`、`RENDER_UNEXPECTED_OVERLAP` 按页统计。
- 视觉覆盖率、连续同构页比例、降级缩放页比例。
- 产物发布前必须满足 0 个 error；warning 需要在任务结果中可追溯。

## 验收标准

1. 节点检测不再依赖 `data-sg-id`，历史任务中无 ID 来源行越界可以被定位到具体 class/文本。
2. 真实 Chromium 审计与 repair loop 使用同一 DOM 测量，避免跨进程字体/缩放漂移。
3. 重新触发历史失败任务，最终任务状态为 `completed`，发布前 error 数为 0；若使用降级缩放，必须明确记录页码与缩放比例。
