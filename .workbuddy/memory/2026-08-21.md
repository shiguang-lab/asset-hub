## 修复：SSR 公开页 presence 恒显「访客」的问题

### 根因
- 公开页 `/p/{slug}`（SSR public-reader）的 presence 心跳请求只发 `visitorId`，未带用户身份。
- 架构上公开页服务端本就拿不到身份：Caddy 对 `/p/*` 会剥离 `__Secure-sg_session` cookie 与 `X-SG-*` 身份头，且该路径**不配置 forward_auth**（身份转换只发生在 `/api/v1/*`、`/mcp/*`）。这是「用户自定义 HTML 与登录主站隔离」的安全设计。
- 因此网关把当前用户记成 `guest:<visitorId>`，Header 渲染「访客」。

### 修复（前端为主，符合安全边界）
1. `apps/ssr/app/components/public-reader.tsx`
   - 新增 `fetchPresenceIdentity()`：浏览器静默请求同源 `/api/auth/session`（未登录返回 401/JSON，不会跳登录），解析 `userId/displayName/avatarUrl`，按页面生命周期缓存（promise 缓存，避免 30s 轮询反复请求）。
   - presence POST body 增加 `userId/displayName/avatarUrl`（登录用户时）。网关/API 已支持这些可选字段，仅前端此前未带。
2. `apps/public-gateway`（仅本地 dev 生效）
   - `config.go` 新增 `AuthBaseURL`（env `AUTH_BASE_URL`，默认 `https://shiguanglab.com`）。
   - `main.go` 新增 `GET /api/auth/session` 反向代理（生产该路径由 access-gateway 的 `@assetHubSharedAuth` 直接路由到 auth-service，不会到网关，无冲突）。
3. `.env.example` 补充 `AUTH_BASE_URL` 说明（broker 模式指 Web dev 服务 localhost:3000）。

### 关键约束（供后续参考）
- 公开页**绝不**调用 `redirectToUnifiedLogin()`；`/api/auth/session` 只返回状态、不重定向，公开页保持匿名可访问。
- 匿名访客会多发一个 `/api/auth/session` 请求（可接受）。
- dev 下公开页在 `localhost:3004`，靠网关代理 `/api/auth/session` 才能认出登录用户；否则走 401 → 访客分支。

## 紧急修复 + 部署：devAuth 强制开启漏洞（2026-08-21 14:0x）

### 严重安全漏洞（C 级）
- 根因：`packages/config/src/index.ts` 中 `devAuth: z.coerce.boolean().default(true)`。`z.coerce.boolean("false")` 实际执行 `Boolean("false")` → `true`，所以生产 `DEV_AUTH=false` **从不生效**，devAuth 一直开着。
- 影响：每个匿名请求都被当作 demo owner（已登录的演示工作区所有者）。后果：① 破坏「评论作者身份由服务端解析」的模型（匿名写评论被当成 owner）；② 权限提升漏洞——未登录即拥有 owner 级访问。
- 生产环境变量：`production.yml` 里 `DEV_AUTH: "false"`、`NODE_ENV: production` 一直正确，但被 coerce 静默吞掉。

### 修复
- 新增 `parseBooleanEnv(value)`：`["true","1","yes","y","on"]` 才为真，其余（含 `"false"`、空、生产下 undefined）为假。
- `loadCommon()` 改为：`DEV_AUTH` 未设置/空 → 看 `NODE_ENV !== "production"`；否则走 `parseBooleanEnv`。schema 字段由 `z.coerce.boolean().default(true)` 改为 `z.boolean()`。
- 本地重建 `@shiguang/config` 的 `dist/index.js`（Docker 构建也会重建，本地同步前也重了，保证 dist 与 src 一致）。
