**1. 产品概述**

**1.1 产品定位**

Shiguang Lab 是一个围绕“知识工作成果在线化”的 AI
原生工作空间。平台帮助个人和团队生产、管理、分析、转换、发布和持续维护数字内容，使
AI 产出不再停留在一次性对话中，而成为可长期访问、复用和协作的数字资产。

| **一句话定位** 一个既能当 Markdown / HTML 在线文档平台使用，也能逐步扩展到知识库、深度调研、数据分析、H5 在线演示、无人值守 Agent 与 MCP 的 AI 原生知识与数字资产工作空间。 |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

**1.2 核心能力**

| **能力域**   | **主要能力**                              | **用户价值**                             |
|--------------|-------------------------------------------|------------------------------------------|
| 文档在线化   | Markdown、HTML、在线阅读、版本、发布      | 低成本管理和在线访问代码类文档           |
| 知识库       | 资料接入、搜索、Ask、Citation             | 把已有资料变成可检索、可问答知识         |
| Research     | 搜索、阅读、数据提取、验证、报告          | 将复杂调研交给系统完成                   |
| Dataset      | 结构化数据、筛选、统计、AI 分析           | 把行业数据从“报告附件”变为可继续分析资产 |
| H5 在线演示  | 从文档/报告生成在线演示、模板、编辑、播放 | 无需 PowerPoint 文件即可在线演示与传播   |
| Agent / Task | 后台执行、Checkpoint、Retry、通知         | 用户关闭页面后任务仍继续执行             |
| Publish      | 稳定 URL、权限、短链、二维码、统计        | 让文档和成果直接成为在线资源             |
| MCP / API    | 搜索、读取、创建和更新 Asset              | 让外部 Agent 直接使用平台知识与资产      |

**1.3 本期不做**

- 不做 Word 类完整富文本编辑器替代。

- 不做 PowerPoint / PPTX 文件编辑器。

- 不做 Canva 类自由拖拽设计器。

- 不做 IM、Jira、完整项目管理、音视频会议。

- MVP 不要求用户配置模型、temperature、Embedding、Vector DB 等底层 AI
  参数。

**2. 产品原则与范围**

**Asset First**

平台核心对象是 Asset，而不是
Chat。文档、报告、数据、演示、图表、来源均可成为长期 Asset。

**弱耦合、强组合**

文档、知识库、Research、数据、演示均可独立使用，但可以通过统一 Action
组合。

**AI Everywhere**

AI 增强所有模块，但基础产品不依赖 AI 也应完整可用。

**Agent When Needed**

简单任务使用 AI Function，固定转换使用 Workflow，复杂长任务才进入 Agent
Task。

**Code First**

确定性解析、统计、转换、渲染优先使用代码，模型用于理解、规划、推理和生成。

**Progressive Disclosure**

普通用户只看到“写文档/建知识库/做调研/做演示”，MCP、模型、调度等高级能力逐层暴露。

**2.1 Asset 类型**

| **类型**     | **示例**              | **可独立创建**   | **可发布** | **可加入知识库** |
|--------------|-----------------------|------------------|------------|------------------|
| Document     | Markdown 文档         | 是               | 是         | 是               |
| HTML         | HTML 页面 / Dashboard | 是               | 是         | 是               |
| Report       | Research 报告         | 由任务或模板生成 | 是         | 是               |
| Dataset      | CSV / JSON / 行业数据 | 上传或任务生成   | 按产品策略 | 是               |
| Presentation | H5 在线演示           | 是               | 是         | 按内容需求       |
| Chart        | 图表                  | 从数据生成       | 可嵌入     | 否/作为来源      |
| Source       | Research 来源         | 任务生成         | 否         | 可作为知识来源   |
| File         | PDF / Office / 图片   | 上传             | 按类型     | 是               |

**3. 用户角色与核心场景**

| **角色**            | **核心需求**                       | **高频入口**                      |
|---------------------|------------------------------------|-----------------------------------|
| 个人专业用户        | 写文档、研究、分析、演示、发布     | 首页 / 文档 / Research / 在线演示 |
| 研究/咨询用户       | 行业研究、竞品分析、Evidence、报告 | Research / Dataset / Templates    |
| 中小企业            | 文档管理、知识库、内部共享         | 资产 / 知识库 / 发布              |
| 开发者 / Agent 用户 | 通过 MCP/API 使用知识和资产        | 设置 \> 连接与集成                |
| 团队用户（P1）      | 共享资产、权限、模板、协作         | Workspace / Team / 权限           |

**3.1 典型场景**

**只写文档**

用户创建 Markdown → 编辑 → 自动保存 → 分享/发布，全程不需要 AI。

**只做知识库**

上传 PDF/Markdown → 索引 → Search / Ask → Citation。

**Markdown 转在线演示**

选择文档 → AI 生成大纲 → 用户确认 → H5 演示 → 编辑 → 发布 URL。

**无人值守行业调研**

输入研究目标 → AI 推荐范围 → 创建任务 → 关闭页面 → 后台执行 → 完成通知 →
Report/Dataset/Sources。

**外部 Agent 使用企业知识**

启用 MCP → 选择可访问知识库/资产 → 生成连接配置 → Claude/Cursor
等直接检索。

**5. 首页与全局入口**

**5.1 首页目标**

首页承担“开始一项工作”和“继续已有工作”两个核心任务。首屏不做传统管理后台，而以一个主输入框 +
Quick Create + 运行中任务 + 最近内容构成。

**首页智能入口**

| **描述目标 → 意图识别 → 即时回答 / 创建文档 / Research / 后台任务 / 引用已有 Asset** |
|--------------------------------------------------------------------------------------|

| **需求ID**  | **需求项**   | **需求描述**                             | **优先级** | **验收标准**                                                     |
|-------------|--------------|------------------------------------------|------------|------------------------------------------------------------------|
| FR-HOME-001 | 主输入框     | 支持自然语言描述目标，可引用已有 Asset。 | P0         | 输入“帮我分析越南消费金融市场”可识别为 Research 并生成推荐范围。 |
| FR-HOME-002 | Quick Create | 提供深度调研、写文档、在线演示、知识库。 | P0         | 一键进入对应创建页。                                             |
| FR-HOME-003 | 运行中任务   | 展示任务名、进度、当前步骤。             | P0         | 点击可进入 Task Detail。                                         |
| FR-HOME-004 | 最近内容     | 展示最近访问或编辑的 Asset。             | P0         | 点击恢复上次工作。                                               |
| FR-HOME-005 | 推荐模板     | 根据用户行为推荐 Research/演示模板。     | P1         | 至少支持模板点击预览与使用。                                     |

**5.2 AI 推荐范围**

复杂 Research 请求不直接执行。系统先自动生成可修改的
Scope，例如市场规模、主要公司、产品、竞争格局、趋势与机会，并默认填充地区和时间范围。高级设置默认折叠。

**18. 权限与安全模型**

**18.1 权限对象**

| **对象**       | **权限**                           |
|----------------|------------------------------------|
| Asset          | Owner / Editor / Viewer / Public   |
| Knowledge Base | 管理 / 添加 Source / Ask / Read    |
| Task           | Owner / Collaborator / Viewer      |
| MCP/API        | Scope + Read/Write                 |
| Publish        | Private / Link / Public / Password |

**18.2 安全要求**

- 统一登录 Token 不在前端长期明文保存。

- HTML/Presentation 中的自定义代码与主站隔离运行。

- MCP/API Token 可撤销、可限 Scope、可审计。

- Research 外部来源保留 URL、抓取时间和来源信息。

- 用户私有 Asset 默认不得用于其他用户检索或模型上下文。

- 删除/永久删除/公开发布/Write 权限等高风险操作需要明确提示。

**19. 状态、异常与恢复**

| **场景**       | **错误表现**           | **恢复操作**              |
|----------------|------------------------|---------------------------|
| 自动保存失败   | Save Failed + 本地草稿 | 重试同步 / 保留本地       |
| 知识库解析失败 | 单 Source Failed       | 重试 / 移除               |
| Task 部分失败  | Partial Completed      | 查看成功结果 / 重试失败项 |
| Agent 全部失败 | Failed + 失败步骤      | 从 Checkpoint 重试        |
| HTML 运行错误  | Sandbox Error          | 查看错误 / 修改 Source    |
| 发布链接过期   | Expired 页面           | Owner 可延长有效期        |
| 权限不足       | 403 友好页             | 申请权限 / 返回           |
| Asset 不存在   | 404                    | 返回资产中心              |
| Credits 不足   | 阻止高成本任务         | 降低模式 / 购买           |
| 网络异常       | 离线提示               | 本地草稿 / 自动恢复       |

**19.1 统一错误原则**

- 错误必须告诉用户“哪个对象、什么阶段、发生了什么”。

- 错误必须尽可能给出下一步可操作按钮，而不是只显示 Error。

- 长任务错误优先局部恢复，不无条件整体重跑。

- 用户输入和已有内容不得因 AI 或网络错误被静默覆盖。

| 数据安全   | Private Asset 不被未授权用户/MCP 访问；HTML 与主站隔离。                                           |
| 成本可控   | 任务执行记录 Credits；确定性任务优先 Code First。                                                  |
| 可观察性   | 任务、索引、发布均有状态、日志或错误信息。                                                         |
| 移动端     | 公开文档与 H5 演示在移动浏览器可正常阅读/播放/分享。                                               |

**附录 B：核心业务流程**

**B.1 文档独立使用**

| **创建 Markdown → 编辑 → 自动保存 → 分享 / 发布** |
|---------------------------------------------------|

**B.2 文档加入知识库**

| **Document → 加入知识库 → 选择/创建 KB → 索引 → Search / Ask** |
|----------------------------------------------------------------|

**B.3 文档生成在线演示**

| **Document → 生成在线演示 → AI Outline → 确认 → H5 Editor → Preview → Publish** |
|---------------------------------------------------------------------------------|

**B.4 Research**

| **输入 Goal → AI Scope → 创建 Task → 后台执行 → Report + Sources + Dataset → 继续操作** |
|-----------------------------------------------------------------------------------------|

**B.5 无人值守恢复**

| **Running → Checkpoint → 步骤失败 → Retry Failed Step → 继续执行 → Completed / Partial** |
|------------------------------------------------------------------------------------------|

**B.6 MCP**

| **设置 → 启用 MCP → 选择 Scope → Read Only → 生成连接配置 → 外部 Agent 检索** |
|-------------------------------------------------------------------------------|

**B.7 组合关系原则**

所有流程均为可选组合，不应把用户强制锁定在“Research → Knowledge →
Presentation → Publish”等固定链路。任意 Asset 页面通过上下文 Action
提供可用的下一步，用户可随时结束流程或切换到其他模块。

**结语**

**Shiguang Lab 的核心价值不在于再做一个 AI
Chat，而在于把“内容在线化、知识资产化、复杂工作任务化、研究数据结构化、成果可发布化、能力可被
Agent 调用”统一到一个弱耦合的产品体系中。**

| **最终产品公式** Asset Platform + Documents + Knowledge + Research + Agent Runtime + Dataset + H5 Presentation + Publish + MCP/API。 |
|--------------------------------------------------------------------------------------------------------------------------------------|

本 PRD V1.0
作为当前产品、交互、研发和测试的统一基线。后续迭代应优先保持模块独立性与组合能力，避免为增加功能而破坏
ToC 简洁心智。
