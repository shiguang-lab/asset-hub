# Obsidian 插件产品设计：文档关联同步与知序工作区

日期：2026-09-11 · 状态：产品设计稿，尚未实现

## 0. 设计审核结论

本稿经用户路径、数据一致性、跨 Vault、实现成本和现有系统能力审核后，采用以下方案：

- 保留「按篇主动关联 + 可选自动双向同步」。它符合用户对同步范围可控、目录不被插件接管的诉求，也是解决误上传和误下载的关键。
- 关联只保存在当前 Vault 的插件数据中。服务端继续以文档 ID 和版本号作为真源，本期不增加 Vault / 设备关联表，也不要求服务端知道用户本地有哪些文件。
- 多个 Vault 的同名文件默认是不同文档；发生云端路径冲突时，在首次同步弹窗中让用户改名创建或明确关联已有文档。系统可以建议带数字的名称，但不自动执行，也不把 Vault 名写入文档标题。
- 多个 Vault 明确关联同一云端文档时，各自维护同步基线，依靠现有条件更新和三方比对防止覆盖。无需建立跨 Vault 的直接关系。
- 侧边自动登录、发布版本与分享设置分离仍是必须项，需要服务端 / 身份服务配合；它们与同步关联存储是不同问题。

曾考虑过「云端登记所有 Vault 来源 + 操作系统级实例注册表」，审核后从本期移除。这套机制会产生陈旧设备记录、额外隐私说明和新的写入授权状态，无法替代本地基线，对安全同步也不是必要条件。只有未来确认存在大量跨设备自动恢复需求时，再单独立项。

## 1. 产品决策

插件提供两类能力：在 Obsidian 原有目录中编辑文档，并按篇关联到拾光文档中心；在 Obsidian 内容区直接使用知序网页。

核心原则：**本地文件留在原处，用户主动选择要同步的文档，云端文档通过稳定 ID 建立关联。** 安装、登录和开启自动同步均不创建业务目录，不扫描上传整个 Vault，也不自动下载整个云端空间。

本稿以「知序」作为侧边入口和网页名称，以「拾光文档中心」作为文档菜单名称。二者指向同一服务中的工作区和文档模块，不代表两个账号或两份数据。

| 决策 | 本期定义 |
| --- | --- |
| 同步单位 | 一篇本地 Markdown 文档 ↔ 一篇云端文档 |
| 本地目录 | 用户自由组织，插件不要求专用目录 |
| 首次同步 | 选择云端工作空间和目录，成功后保存关联 |
| 后续手动同步 | 「同步到文档中心」明确表示本地上传；「从文档中心拉取」明确表示云端下载 |
| 自动同步 | 默认关闭；开启后，仅已关联文档参加双向内容同步 |
| 目录与命名 | 本地路径、文件名与云端目录、标题分别管理，移动或重命名不传播到另一侧 |
| 删除 | 任一侧删除均不自动删除另一侧，不自动重建被删内容 |
| 发布 | 用户主动发起，使用一个「发布与分享…」入口复用现有弹窗；同步不会更新公开版本 |
| 侧边入口 | 打开内容区的「知序」标签页，首次进入文档中心 |
| 公开入口 | 登录、OAuth 请求和知序页面统一从 `https://shiguanglab.com` 进入；文档资源 API 使用 `https://doc.shiguanglab.com/api/v1` |
| 平台范围 | 桌面端；本地同步仅 `.md`，网页保留其现有在线能力 |

成功条件：用户不移动本地文件即可完成首次同步；后续操作不重复选目录；单边修改可安全收敛、双边修改不丢失；插件已登录时打开知序和发布弹窗不重复登录。

## 2. 现有实现评估

以下结论来自当前仓库代码检查，未进行运行时复现。旧设计文档包含阶段性描述，本稿的现状判断以代码为依据。

| 当前行为 / 能力 | 依据 | 设计判断 |
| --- | --- | --- |
| 默认根目录为「拾光资产中心」，同步、启动同步、实时监听默认开启 | `src/settings.ts` | 改为显式关联、自动同步默认关闭 |
| 枚举根目录 Markdown，并拉取所有尚未绑定且有路径的云端文档 | `src/sync/engine.ts`、`differ.ts` | 会扩大同步范围、产生业务目录；取消此发现即同步逻辑 |
| 已有内容哈希、远端版本号、三方比对和条件更新 | `src/sync/hash.ts`、`differ.ts`、`api/documents.ts` | 保留基础机制，但不能仅依赖先拉后推的执行顺序保证安全 |
| 云端移动优先于本地内容修改判断，拉取时写入新路径并回收旧文件 | `differ.ts` 的 `classify`、`engine.ts` 的 `#pull` | 存在移动与本地编辑并发时覆盖修改的风险；内容与路径彻底解耦 |
| 删除本地文件且保留云端时会解除索引，下一轮未绑定云端又能被拉回 | `differ.ts` | 改为保留异常关联状态，并且禁止自动发现未关联文档 |
| 默认允许云端删除传播到本地 | `src/settings.ts` | 取消删除传播 |
| 冲突会在笔记旁创建副本；拉取正文与记录版本分开，解决冲突使用的版本可能陈旧 | `engine.ts`、`api/documents.ts` | 保留双份保护目标，改为插件内部快照；正文和版本须一致读取 |
| 侧边图标打开右侧同步状态面板；没有文档右键同步、目录选择和插件发布入口 | `src/main.ts` | 增加文档操作，调整侧边主入口 |
| 插件通过 OAuth Bearer 调 API，网页通过 Cookie 查询会话 | `src/auth/oauth-client.ts`、`apps/web/src/auth/session.ts`、`entities/api.ts` | 不能假设插件 token 就是网页登录态，需增加会话衔接 |
| 网页已有目录数据读取、发布弹窗和发布版本构建 | `documents.tsx`、`publish-dialog.tsx`、`apps/api/src/modules/publishing.ts` | 复用产品能力，不在插件中另造发布表单 |

结论：现有双向同步的基础方向可用，但「目录镜像」模型不适合本次需求。应保留认证、条件更新、事件监听等基础能力，重新定义同步范围、绑定、冲突、删除和交互入口。

## 3. 入口与信息架构

### 3.1 Obsidian 侧边主入口

左侧 Ribbon 只保留一个「知序」图标，放在 Obsidian 默认入口之后，提示文案「打开知序」。点击后在中央内容区打开独立的「知序」标签页，首次地址为 `https://shiguanglab.com/documents`。保留原文档标签页及编辑状态，不替换或关闭正在编辑的笔记。

再次点击激活已有知序标签页，保留当前网页位置，不反复创建标签或跳回首页。关闭后再次打开进入文档中心。本期不设计多个在线应用入口或在线演示专属按钮。

**侧边点击即自动进入已登录的知序页面。** 插件已有 OAuth 授权时，全程复用该身份，不显示网页登录页、登录按钮或二次授权确认，也不打开系统浏览器要求登录。会话准备属于后台加载过程，不是用户需要完成的步骤。

标签页内呈现现有知序网页，支持原有浏览、搜索、目录管理、编辑和发布等在线操作。网页新建文档不会自动写入 Vault；只有已关联文档的云端变更才参与自动同步。网页中已有演示等功能可按原有权限使用，但本期不提供演示文件同步或专用本地集成。

| 标签页状态 | 展示与行为 |
| --- | --- |
| 插件从未授权或用户已主动退出 | 由插件统一启动首次 OAuth 登录流程，完成后自动继续原目标；内嵌页面不提供独立登录入口 |
| 已登录、会话衔接中 | 「正在打开知序…」，成功后直接展示网页 |
| 离线 | 「当前离线，联网后重试」；本地编辑照常 |
| 网页会话或访问令牌过期 | 插件静默刷新并自动恢复网页会话，不跳网页登录页；仅 OAuth 授权被撤销或刷新凭据失效时，由插件统一提示重新授权 |
| 页面加载或会话衔接失败 | 保留目标地址，提供「重试」及具体失败原因；不能回退到网页登录页或以浏览器登录代替自动登录 |
| 权限不足 | 展示无权限原因与返回文档中心入口，不切换到其他空间执行写入 |

### 3.2 同步状态入口

同步状态保留在 Obsidian 底部状态栏，点击打开右侧「文档同步」面板，不占用主 Ribbon 图标。

状态栏示例：`文档同步：自动同步已关闭`、`文档同步：同步中 2/5`、`文档同步：2 篇待处理`。错误和冲突优先于普通状态；无异常时显示自动同步开关状态及最近成功时间。

面板显示本 Vault、当前账号及空间的已关联文档：本地路径、云端目录、同步状态、最近成功时间、错误原因。支持「全部 / 待同步 / 待处理」筛选，以及「同步全部已关联文档」「打开设置」。全量按钮执行安全双向比对，手动模式下也可使用，冲突文档跳过并列出，不提供批量强制覆盖。

行操作沿用文档菜单。首次为空时提示：「在 Markdown 文档菜单中选择『同步到文档中心…』，开始关联第一篇文档。」

### 3.3 文档菜单

文件列表右键和当前文档更多菜单使用同一组「知序」二级菜单；操作始终针对被点击的文档。插件通过桌面端 `MenuItem.setSubmenu()` 创建原生子菜单。非 Markdown 文件、文件夹、多选文件本期不显示这组操作。

```text
未关联文档                         已关联文档
知序 > 同步到文档中心…               知序 > 同步
                                     知序 > 拉取云端版本
                                     知序 > 发布与分享…
                                     知序 > 在文档中心打开
                                     知序 > 解除同步
```

说明：省略号表示进入选择或确认界面；不用 Push / Pull 作为用户文案。未关联文档先同步，再提供发布功能，避免隐式创建云端文档。「发布与分享…」在弹窗内承载首次发布、更新发布内容、分享设置和复制链接，避免右键菜单随发布状态不断膨胀。

| 条件 | 菜单行为 |
| --- | --- |
| 未登录 | 保留可识别入口，点击后登录并继续原操作；不自动执行首次上传 |
| 正在处理当前文档 | 上传、拉取、发布更新暂不可重复执行；详情仍可打开 |
| 有冲突 | 上传和拉取进入冲突处理，发布/更新发布禁用并说明「请先处理同步冲突」 |
| 离线 | 在线动作禁用并说明原因；详情和解除同步可用，不排队发布动作 |
| 云端只读 | 拉取、在线打开可用；上传和发布按权限禁用 |
| 关联失效 | 保留详情、解除同步及适用的恢复操作，不把文档当作首次同步静默重建 |

命令面板提供：打开知序、同步当前文档到文档中心、从文档中心拉取当前文档、同步全部已关联文档、打开文档同步面板。账号操作集中于设置；当前文档命令与菜单采用相同校验。

## 4. 首次关联与后续手动操作

### 4.1 首次同步

用户点击「同步到文档中心…」后打开原生选择弹窗：

1. 展示当前账号、工作空间、本地文件路径；本地路径只读。
2. 选择云端目录，支持目录树、搜索、根目录及新建目录；数据使用云端真实目录能力。默认选中同账号、同空间最近使用目录，没有记录则为根目录，但每篇首次同步仍需确认。
3. 云端标题默认取本地文件名去掉 `.md`，允许修改。预览完整云端位置；保存的是云端实际路径格式，不把 `.md` 或本地目录自动带入。
4. 明示：「仅同步当前文档，保留本地位置。自动同步当前已关闭 / 已开启。」
5. 点击「同步并建立关联」后上传当前已保存内容；成功后落盘关联、基线与远端版本。取消不创建文档或绑定。

同目录同名冲突按 §4.5 处理：默认建议改名创建独立文档，明确确认后执行；不得自动覆盖或按路径认领。用户也可明确选择「关联已有文档」。关联已有文档需预览双方正文及差异；内容相同时直接确认关联，内容不同时选择「使用本地内容」「使用云端内容」或取消；覆盖前保存被替换内容，完成一致性校验后建立基线。

重试规则：创建成功但响应丢失或索引写入失败时，不得再次创建重复文档。首次创建需具备可恢复的请求标识和结果查询能力；这属于待补能力，不假设现有接口已支持。若无法确认结果，显示「同步结果待确认」，禁止盲目重建。

### 4.2 同步到文档中心

后续按绑定 ID 上传，不再选择目录；上传只更新正文，保留云端现有标题与目录。先检查远端版本：

- 仅本地修改：条件更新成功后记录新基线，提示「已同步到文档中心」。
- 双方内容相同：更新基线，不创建无意义版本。
- 云端正文已修改：不隐式覆盖或切换为下载，进入差异确认；若仅云端有修改，提示「云端有更新，请拉取，或明确选择使用本地内容」。
- 本地没有待上传内容且云端正文未变：提示「文档已是最新」。

自动同步关闭只关闭后台调度，不影响手动上传、拉取、全部同步和发布前检查。

### 4.3 从文档中心拉取

按绑定 ID 获取最新正文，写回原文件路径，不复制到专用目录。远端无更新且本地有修改时，不静默丢弃本地修改；提示「本地有未同步修改」，由用户选择保留本地并取消，或确认使用云端内容。

只要拉取会覆盖本地未同步内容，就必须展示差异与确认，并保存本地快照。执行写入前再次检查编辑器缓冲区与磁盘内容；若用户继续输入，取消本次覆盖并重新比较。已是最新时不重写文件。

### 4.4 解除同步

确认文案：「解除后，此文档不再参与同步。本地文件、云端文档和已有分享链接均保留。已发布内容不会撤回。」主按钮「解除同步」。

确认后取消未执行任务；在途任务结束前等待结果或阻止其回写绑定，避免解绑后被重新关联。移除活动绑定，保留尚未处理的恢复快照。重新同步视为首次关联，不凭文件名自动找回关系；可明确选择原云端文档。

解除同步不要求联网。若正在发送的上传已经抵达服务端，不能承诺撤销该次上传，界面显示最终结果。

### 4.5 多个 Vault 的同名文档

**默认是独立文档，只有明确关联才成为同一篇文档。** 名称、目录、内容哈希都不能单独证明文档身份。即使两个 `周报.md` 正文完全一样，也不自动合并。

示例：Vault「工作」中的 `记录/周报.md` 已关联云端 `团队/周报`，Vault「个人」的 `笔记/周报.md` 首次同步到 `团队` 时：

| 用户选择 | 云端结果 | 后续行为 |
| --- | --- | --- |
| 默认：创建独立文档 | 弹窗建议 `团队/周报 (2)`，用户确认后创建新的文档 ID | 两篇各自同步，互不覆盖；两个本地文件仍叫 `周报.md` |
| 修改目标目录或标题 | 按用户预览确认的位置创建新文档 ID | 各自维护关联 |
| 主动选择：关联已有文档 | 选择现有 `团队/周报` 的 ID，不创建新文档 | 两个 Vault 的文件成为同一云端文档的本地副本，双向同步可传播彼此修改 |
| 取消 | 不创建、不覆盖、不建立关联 | 本地保持未关联 |

重名处理直接出现在首次同步弹窗内，不额外套一层确认框：显示现有文档的更新时间和正文摘要，并提供「改名创建」与「关联已有文档」。选择改名创建时预填可用标题，主按钮为「创建独立文档并同步」；选择关联时先比较正文。**系统只生成建议，不静默改名、覆盖或关联。**

命名规则：没有冲突时使用原文件名；有冲突时建议 `原标题 (2)`、`原标题 (3)`，取最小可用编号。Vault 名称属于本地组织信息，不自动写入云端标题；用户认为 Vault 名有辨识价值时可以自行修改。标题长度、非法字符和规范化与服务端路径校验一致，超长时保留后缀并缩短原标题，完整预览最终名称。

该规则也适用于同一 Vault 不同本地目录里的同名文件，以及云端由网页创建的同名文档。已经关联成功的文档不再执行命名分配；重试、重启、Vault 改名和后续上传均不能追加后缀或新建副本。

目录可用性检查只用于提前提示。提交时以服务端路径唯一约束为准：若其他客户端抢先占用目标，保留弹窗和用户输入，刷新建议名称，由用户重新确认，不静默改成下一个编号。当前代码已有工作空间内路径唯一约束、`ASSET_PATH_CONFLICT` 以及创建幂等回执；插件需要接入这些能力和上述交互，不需要新增重名记录表。

### 4.6 多个 Vault 主动关联同一篇云端文档

「关联已有文档」展示云端目录、标题、正文预览和更新时间。确认文案：「此本地文件将与所选云端文档双向同步。该文档也可能由网页、其他设备或其他 Vault 编辑。」不能只显示「存在同名文件，是否覆盖」。服务端无需记录或暴露具体 Vault 来源。

关联关系是多对一：各本地副本分别绑定同一远端 ID，各自维护基线、待同步状态和冲突；不是两份本地文件直接互相同步。一个 Vault 实例内不允许两个路径绑定同一远端 ID，命中时直接提示已关联的本地路径，提供「打开本地文档」，不再创建第二份关联。

例如 A、B 均基于云端 v1：A 上传后产生 v2，B 没有修改则拉取 v2；B 也修改了正文则进入冲突，不直接覆盖 v2。A、B 同时提交时由服务端条件更新裁决，失败的一方重新比较。各副本自动同步开关独立，关闭 B 的自动同步不会影响 A。

解除 A 的关联只停止 A；B、云端文档和分享链接保持。云端改名仍沿用远端 ID，不要求所有 Vault 跟着改名。不能仅因云端同名路径被删除后重新创建，就把旧关联转给新 ID。

同步详情显示「本地文件 ↔ 云端文档」关系、云端文档 ID、目录和最近同步状态，供用户确认当前绑定。它不展示“其他关联 Vault”；插件只需按普通多人 / 多端编辑处理所有远端变化。

## 5. 自动双向同步

### 5.1 范围与触发

设置项「自动双向同步」默认关闭，说明：「自动同步当前 Vault 中已关联文档的内容，不同步目录结构、删除操作或发布状态。」开启时展示参与文档数，不扩大范围。

开启后，本地停止编辑并保存约 3 秒触发；云端相关文档事件约 2 秒合并触发；5 分钟周期检查用于补漏。插件启动、重新登录及网络恢复后补一次比对。用户在 Obsidian 内编辑的文档以已保存内容为上传输入，尚未保存内容仍须计入拉取覆盖保护。

只处理绑定 ID，远端事件按空间和文档过滤；事件仅是重新读取的信号，不直接当作权威正文或删除证明。关闭自动同步时停止监听触发、计时和待执行后台任务；在途任务安全结束，其结果如实记录。

自动同步仅在 Vault 打开、插件运行且网络可用时工作。Vault 关闭后不提供后台守护承诺。未关联文件的新建、修改、复制及云端新建均不触发关联。

### 5.2 内容决策矩阵

以最近一次双方成功一致的内容为基线 B，比较当前本地 L 与云端 R。不能用更新时间决定胜负；远端版本变动也可能只是标题、目录等元数据变化。

| 本地正文相对 B | 云端正文相对 B | 自动同步结果 |
| --- | --- | --- |
| 未变 | 未变 | 不写正文；必要时更新远端元数据和版本 |
| 已变 | 未变 | 上传 L，使用当前远端版本进行条件更新 |
| 未变 | 已变 | 拉取 R，覆盖前复核本地未出现新编辑 |
| 已变 | 已变，且 L = R | 直接收敛基线，无冲突 |
| 已变 | 已变，且 L ≠ R | 标记冲突，暂停此文档，其他文档继续 |
| 无可靠基线 | 任意 | 重新核对关联与内容，不能判定覆盖方向 |

所有写入均串行到单篇文档。读取的正文、内容哈希、版本必须来自同一快照；上传前遇到版本变化重新比较，下载写入前遇到本地变化重新比较。成功响应只能确认本次提交的内容，不能把发送后产生的新编辑误标为已同步。

引擎自身写回允许触发一次复核，但内容相同不再创建版本；不得形成上传、下载循环。关闭或解绑后的过期任务不得复活同步。

### 5.3 冲突处理

正文冲突不自动合并、不使用「最后修改者覆盖」。在「文档同步」面板中置顶，状态栏提示一次，后台不反复弹窗。

处理弹窗展示本地内容、云端内容、最近同步基线及差异，提供：

- **使用本地内容**：确认后条件更新云端，保留被替换云端快照。
- **使用云端内容**：确认后写回本地，保留被替换本地快照。
- **稍后处理**：不改变双方内容，保持暂停状态。用户可先手工合并到本地再选择使用本地内容。

快照存储于插件数据目录，不在普通笔记目录生成冲突文件；支持「导出副本…」由用户选位置。未解决快照不自动清理；解决后的快照保留 30 天，在同步详情中可查看和导出。快照不参加同步，卸载前需导出重要快照。

点击处理动作时再次校验双方版本；如果任一侧又变化，刷新差异，不沿用旧确认。处理成功后恢复该文档的自动同步资格。

### 5.4 移动、删除与异常状态

| 事件 | 规则 |
| --- | --- |
| 本地移动或重命名 | 更新绑定的本地路径，远端 ID、目录与标题不变；文件夹移动更新其中已关联文件的本地定位 |
| 云端移动或重命名 | 更新绑定的云端展示位置，继续关联同一 ID，本地文件不移动、不改名 |
| 复制本地文件 | 新文件未关联，即使内容完全相同也不自动关联 |
| 插件离线期间本地移动 | 无法可靠定位时标记「本地文件缺失」，让用户重新选择本地文件并核对内容；不仅凭同哈希猜测身份 |
| 本地删除 | 标记「本地文件缺失」，暂停此绑定；可「选择本地文件…」「从云端恢复…」或解除同步；恢复需用户选择路径并检查占用 |
| 云端明确删除 | 标记「云端文档已删除」，保留本地，暂停绑定；可「重新同步为新文档…」或解除同步，重建需再次选目录 |
| 网络失败、列表缺项或无权限 | 不是删除证据；标记「连接失败」或「云端不可访问」，不删除、不重建 |
| 目标本地路径被其他文件占用 | 不覆盖，要求选择其他路径或取消 |
| 索引损坏 / 丢失 | 暂停自动同步并保留文件，尝试恢复有效索引备份；不得重置后扫描上传或下载全部内容 |
| 账号或工作空间切换 | 按服务、账号、空间隔离绑定，暂停非当前上下文任务；不把旧内容上传到新空间 |

本期一个 Vault 在一个时刻使用一个账号与工作空间，同一上下文内一个本地文件只能绑定一篇云端文档，且同一云端文档不能绑定本 Vault 的两个文件。不同 Vault 可主动关联同一云端文档，各自以独立基线处理并发冲突，不自动复制关系。

### 5.5 内容边界

按 Markdown 原文同步，包括 Frontmatter；仅统一换行进行哈希比较，不注入同步 ID，不删除未知语法。附件、图片文件、Canvas、HTML 文件不参加本期本地同步。

本地图片路径、双链、嵌入笔记和插件语法保留原文，不承诺云端能直接解析。首次同步检测到这些引用时提示「正文可同步，本地附件及 Obsidian 专有引用可能无法在云端显示」，允许继续正文同步；发布前再次列出已发现的本地引用问题。已有云端资源引用沿用现有发布引用确认，不把本地附件上传纳入隐含动作。

如果云端正文类型变为无法无损写回 Markdown 的内容，标记「内容格式不支持」，暂停拉取。验收需覆盖 Frontmatter、代码块、双链、图片引用在上传—下载往返后的原文保留。

## 6. 发布与分享

### 6.1 入口和内容选择

发布以已关联云端文档为对象，复用 Web 的 `PublishDialog`。插件点击后，在中央知序标签页定位对应文档并自动打开该弹窗；不是仅跳到详情页让用户再次寻找发布按钮。

首次发布、更新发布内容先执行单篇安全双向比对，使用户能确认即将发布的正文。自动同步关闭时仍执行此检查；发现冲突、登录失效、读取失败或权限不足则停止流程。此过程不能悄悄用本地覆盖云端。

弹窗显示当前云端版本与内容预览。若同步完成后又出现新编辑，提示「内容已变化，请重新检查后发布」，不将更晚的内容无提示发布。服务端须验证确认时的版本或发布指定版本快照，此能力需在实现阶段补齐。

### 6.2 复用范围与发布状态

沿用现有弹窗的访问方式、密码、有效期、下载和复制权限、发布草稿、引用资源确认、分享短链及二维码。保留现有校验与失败反馈；取消弹窗不产生发布，但此前明确完成的文档同步保留。

| 发布状态 | 「发布与分享…」弹窗行为 |
| --- | --- |
| 未发布 / 已撤回 | 展示「发布并生成短链」，最终确认才生成可访问版本 |
| 有有效发布 | 展示分享链接、复制链接、访问设置和「更新发布内容」 |
| 云端内容比发布版本更新 | 同步详情标记「有未发布更新」；旧链接仍展示旧快照 |
| 更新发布失败 | 保留原有效发布版本，提示失败，不把同步成功等同发布成功 |
| 链接过期 | 在同一弹窗中修改有效期；不误报为同步失败 |

自动同步、手动上传、拉取和解除同步均不触发发布或撤回。撤回入口放在现有知序分享管理中，不增加文档菜单的危险快捷动作。

**必须处理的现有语义差异**：当前服务端 `PATCH /api/v1/publishes/:id` 保存分享设置时也会重建发布版本。新设计要求「分享设置」仅改变访问配置，不夹带未发布正文；「更新发布内容」才显式更换正文快照。复用弹窗时需一并调整这个共用行为：配置变更若需重新生成静态资源，仍基于当前已发布正文快照；更新正文继续使用现有 release 能力并增加版本确认。不能仅在插件外层改按钮名。

分享链接的返回以服务端有效发布为准，不自行拼接。复制链接不触发同步或更新发布。保存分享配置、更新发布内容也要保留现有引用资源的访问确认。

## 7. 登录打通与内嵌网页

**自动登录是本期必须交付的功能：插件完成一次 OAuth 登录后，侧边打开知序、刷新网页、重新打开标签页及打开发布弹窗，均自动使用插件身份进入目标页面。** 不增加第二套登录流程，不要求用户再次点击登录或授权。

唯一身份入口是插件 OAuth。只有从未授权、主动退出、授权被撤销或刷新凭据失效时，才由插件处理首次登录或重新授权。网页缺少 Cookie、网页会话到期和会话衔接失败均不代表插件未登录，不能据此跳转网页登录页。

### 7.1 服务归属与公开入口

所有身份协议与授权状态统一由 `auth-service` 实现，包括 OAuth 元数据、授权状态、授权码、访问令牌、刷新令牌、撤销、内嵌网页会话票据和网页会话建立。`website` 只承载与现有登录页一致的设备确认界面，通过 auth-service 的同源 JSON 接口读取客户端信息并提交决定。插件、website 和 asset-hub api 不自行签发或刷新身份凭据。

外部调用始终使用 `https://shiguanglab.com`。该域名是稳定的产品与认证入口，由边缘网关将认证路径转发到 `auth-service`；不得把 auth-service 的内部域名、容器地址或端口暴露给插件。插件通过 OAuth 元数据发现具体端点，但必须校验元数据的 issuer 和端点均为允许的 `https://shiguanglab.com` 源，避免被配置或网络响应引向其他身份服务。

下列是产品要求的公开契约。设备授权和网页会话票据均是目标设计，实际可用性需要与 auth-service 部署联调确认。

| 用途 | 公开入口 | 归属 / 状态 |
| --- | --- | --- |
| OAuth 元数据 | `GET https://shiguanglab.com/.well-known/oauth-authorization-server` | auth-service |
| 创建登录会话 | `POST https://shiguanglab.com/oauth/device/authorize` | auth-service，本期改造 |
| 登录与授权页面 | `GET https://shiguanglab.com/oauth/device` | website；通用 App 授权界面 |
| 读取授权上下文 | `GET https://shiguanglab.com/oauth/device/context` | auth-service |
| 提交授权决定 | `POST https://shiguanglab.com/oauth/device/decision` | auth-service |
| 设备码兑换与刷新 | `POST https://shiguanglab.com/oauth/token` | auth-service，本期改造 |
| 退出与撤销 | `POST https://shiguanglab.com/oauth/revoke` | auth-service |
| 申请内嵌会话票据 | `POST https://shiguanglab.com/oauth/web-session-ticket` | auth-service；要求 `obsidian-asset-hub` access token 和 `web:session` scope |
| 消费票据并进入知序 | `GET https://shiguanglab.com/oauth/web-session?ticket=…` | auth-service；跳转目标在创建票据时绑定 |
| 知序页面 | `https://shiguanglab.com/documents` 等 | Web 页面入口，不签发 OAuth 令牌 |
| 文档同步 API | `https://doc.shiguanglab.com/api/v1` | asset-hub api，校验 Bearer token 并处理业务数据 |

`return_to` 只接受 `https://shiguanglab.com` 同源站内路径，不能接受外部 URL。票据一次性使用、有效期不超过 60 秒，绑定 OAuth 客户端、账号、工作空间和目标页面；消费后立刻 303 到不含票据的地址，避免票据留在历史记录、日志和后续请求引用中。

### 7.2 自动登录流程

本期选择**插件身份换取受限网页会话**作为衔接方向，以下是待实现契约，不是现有端点：

1. 插件使用已有有效 OAuth 身份向 auth-service 申请短时、一次性网页会话票据，绑定账号、工作空间、目标站点和本次打开请求。
2. 内嵌容器先打开 auth-service 的票据消费入口。auth-service 在执行普通网页登录校验前消费票据、写入 HttpOnly 网页会话，再进入文档中心或指定文档及发布弹窗；不得先加载普通页面跳到 `/login`，再尝试补登录态。
3. 插件 OAuth 客户端新增 `web:session` scope，首次授权页说明「允许在 Obsidian 中打开知序」。会话票据接口只接受同时具有该 scope、`client_id = obsidian-asset-hub` 且 audience 包含 auth-service 的访问令牌。asset-hub api 继续只按文档 scope 授权；不能把仅有 `documents:*` 的令牌静默换成完整网页会话。
4. OAuth 刷新令牌不交给网页；长期令牌不放入 URL、网页本地存储或日志。启动凭据过期或重复使用失效，消费后清理地址，不允许任意站点或重定向使用。
5. 内嵌模式中的会话缺失和 401 交由插件恢复身份，替代网页现有的直接登录跳转。插件静默刷新 OAuth token、向 auth-service 重新申请票据并恢复原目标；恢复失败显示可重试错误，只有 OAuth 授权本身失效才由插件提示重新授权。任何情况下内嵌网页均不展示独立登录页。

内嵌页面不能访问 Node 或 Vault 文件系统。文档定位与「打开发布弹窗」使用明确限定的动作；网页向插件反馈完成、退出等事件时验证来源、会话及目标文档，不能接收任意文件读写指令。

页面会话与插件绑定同一账号、空间。内嵌网页中的退出登录统一退出当前 Vault 插件身份并停止同步；切换空间通过插件设置完成，网页不得独立切换后继续操作旧绑定。系统浏览器的既有会话不受影响。

需先验证实际 Obsidian 桌面内嵌容器、站点嵌入策略、Cookie 和身份服务衔接是否可用。当前仓库不足以证明外部身份服务已具备会话兑换能力；这是实施依赖。验收不能以「打开系统浏览器」代替免重复登录的内嵌体验。

### 7.3 首次 OAuth 登录的回传方式

采用 OAuth 2.0 Device Authorization Grant 作为插件唯一的首次登录流程。整个浏览器过程只访问 `https://shiguanglab.com`，不启动本地 HTTP 服务，不出现 `127.0.0.1` 页面，也不要求注册自定义 URL Scheme。

这里没有传统的 OAuth `redirect_uri` 回调到插件。浏览器在 auth-service 中完成登录与授权后更新服务端登录会话状态；Obsidian 通过轮询 token endpoint 得知结果：

1. 插件调用 `POST https://shiguanglab.com/oauth/device/authorize`，传入 `client_id` 和 scope。
2. auth-service 创建登录会话并返回高熵 `device_code`、便于用户核对的短 `user_code`、`verification_uri`、`verification_uri_complete`、`expires_in` 和 `interval`。
3. 插件保存 `device_code`，在 Obsidian 中显示短码，然后用系统浏览器打开 `verification_uri_complete`。URL 可以携带用户码或等价的一次性会话标识，不能携带 `device_code`。
4. 浏览器已有统一登录会话时直接进入授权确认；未登录时先登录，再回到同一授权会话。website 根据注册表返回的数据展示客户端名称、申请权限和一致的短码，不写死 Obsidian 文案；用户确认后由 auth-service 将登录会话标记为已批准。
5. 插件从发起后就按 `interval` 调用 `POST https://shiguanglab.com/oauth/token`，使用 `grant_type=urn:ietf:params:oauth:grant-type:device_code`、`device_code` 和 `client_id`。收到 `authorization_pending` 继续等待；收到 `slow_down` 后增加间隔；收到 access token 和 refresh token 即确认登录成功并停止轮询。
6. 浏览器在原确认页展示「连接成功，可以返回应用」。它不需要向插件回调，也不展示或接收 token。

用户拒绝时返回 `access_denied`，会话过期时返回 `expired_token`，插件被关闭、取消登录或启动新的登录会话时停止旧轮询。网络超时采用退避，不能越过服务端声明的最小间隔。默认有效期建议 10 分钟、初始间隔至少 5 秒。

用户所说的“身份 ID”在标准协议中拆成两个值：

| 值 | 谁生成 | 谁可见 | 用途 |
| --- | --- | --- | --- |
| `device_code` | auth-service | 只给插件和 token endpoint | 登录会话的持有证明，用于轮询换 token；高熵、短时、一次性，禁止写日志或放入浏览器 URL |
| `user_code` | auth-service | 插件和用户 | 让用户确认授权的是眼前这台客户端；短且可读，不能单独换 token |

插件可以另外生成普通请求追踪 ID，但它不能成为认证凭据。不要使用“插件本地生成一个 ID，网页凭这个 ID 授权”的自定义协议；由 auth-service 签发 `device_code` 才能统一处理过期、限速、拒绝、一次性兑换和审计。

## 8. 设置与同步详情

| 设置分组 | 内容 / 默认值 |
| --- | --- |
| 账号 | 当前账号、工作空间、登录 / 退出 / 切换空间；切换前说明旧空间关联将暂停 |
| 同步 | 自动双向同步：关闭；说明作用范围与后台运行条件 |
| 显示 | 显示同步状态栏：开启 |
| 诊断 | 错误记录、调试日志开关：关闭；日志不含正文或凭据 |
| 服务 | 正式版固定使用 `https://shiguanglab.com` 和 `https://doc.shiguanglab.com/api/v1`，不向普通用户提供修改入口；开发构建可通过开发配置覆盖 |

取消普通设置中的同步根目录、删除传播开关、独立实时同步开关、独立启动同步开关和同步间隔。自动同步开关统一控制这些触发方式，避免出现「关闭定时同步但文件仍自动上传」的误解。

「同步详情」显示：本地路径、云端标题和目录、账号空间、同步状态、最近成功时间、待处理原因、云端版本、当前发布状态、恢复快照入口。同步与发布状态分开显示，例如「内容已同步 · 有未发布更新」。

成功静默用于后台同步，用户主动操作给出简短结果。失败必须定位到具体文档并可重试；批量部分失败显示「3 篇成功，1 篇失败」，不能统一显示「同步完成」掩盖失败。重试只重做失败项，发布动作不自动重试为新的公开操作。

### 9.2 关联记录：身份、存储与恢复

#### 身份与约束

关联属于本地 Vault，不属于云端目录。服务端文档已有稳定 ID；本地只需记录“当前文件关联哪个云端 ID”以及三方比对基线。

| 字段 | 用途 |
| --- | --- |
| `schemaVersion` | 本地账本结构版本，用于安全升级 |
| `bindingId` | 本地关联 ID；建立后不随文件移动变化 |
| `localPath` | Vault 内相对路径；重命名事件发生时更新 |
| `serverOrigin`、`accountSubject`、`workspaceId` | 防止切换服务、账号或空间后串写 |
| `remoteId` | 云端文档的唯一身份；标题和目录不能代替它 |
| `remotePath`、`remoteTitle` | 最近一次观察到的展示信息，不用于判定是否是同一文档 |
| `baseHash`、`baseSnapshotRef`、`remoteVersion` | 最近一次双方一致的正文与服务端版本，用于三方比对 |
| `status`、`lastSuccessAt`、`pendingOperation` | 冲突、缺失、失败和操作恢复 |

同一 Vault、同一账号空间内，一个本地路径只能有一条活动关联，一个远端 ID 也只能关联一个本地路径。另一个 Vault 可以明确关联同一远端 ID，它拥有自己的账本和基线，服务端无需知道二者关系。

#### 存储位置

关联记录与快照放在 Obsidian 插件配置目录，默认位于 `<Vault>/.obsidian/plugins/asset-hub-sync/`。这是隐藏的插件数据，不在笔记区创建业务目录，也不修改 Markdown 或 Frontmatter。

```text
<插件目录>/
  data.json                 设置、账号摘要和经系统密钥加密的凭据密文
  sync-index.json           关联、哈希、版本、状态和待恢复操作
  sync-index.backup.json    最近一次有效备份
  sync-snapshots/           基线、冲突和覆盖前恢复快照
```

索引采用临时文件写完再替换，成功解析后更新备份。快照正文不得进入日志；按 §5.3 保留和清理。用户可从同步详情查看索引位置、导出恢复快照或清除已解决记录。

不增加操作系统级 Vault 注册表，不把本地绝对路径、Vault 名称、关联清单和快照上传服务端。OAuth 凭据与关联数据逻辑分开：访问令牌和刷新令牌不得以明文存入可被 Obsidian Sync 或 Git 同步的插件数据，桌面端应使用 Electron `safeStorage` 或等价的系统凭据保护；换设备后重新进行一次 OAuth 授权。拥有一份复制来的账本不代表已取得对应账号权限。

#### 写入与失败恢复

1. 首次创建前生成并持久化 `pendingOperation` 和幂等键，再调用现有 `POST /assets`。仓库已经支持 `Idempotency-Key` 与回执保存，应直接复用；相同操作重试返回同一文档，不能产生重名副本。
2. 云端成功后写入 `remoteId`、返回版本和正文基线，账本落盘后才报告关联完成。若落盘失败，保留操作记录，重启后使用同一幂等键恢复。
3. 上传继续使用现有 `If-Match`；下载需要正文、哈希和版本来自同一远端快照。任何一侧在写入前变化都重新比较。
4. 解除同步只需本地移除活动关联，不调用服务端，也不影响云端文档、其他 Vault 或分享链接。离线即可完成；已发出的请求仍显示最终结果。
5. 账本损坏先尝试有效备份。没有可靠基线时，允许用户通过「关联已有文档」选择远端 ID 并比较双方正文；内容相同可直接重建基线，内容不同必须选择版本，不能全盘扫描后自动恢复。

#### 移动、复制、换设备与卸载

| 场景 | 行为 |
| --- | --- |
| Vault 在本机改名或整体移动 | 关联使用 Vault 内相对路径，插件数据随 Vault 移动；正常打开后继续使用，无额外确认 |
| 插件运行时移动或重命名文档 | 更新 `localPath`，远端身份不变 |
| 插件未运行时移动文档 | 原路径找不到时标记缺失；允许用户选择新位置，核对内容后恢复，不仅凭同名自动认领 |
| 完整复制 Vault（包含插件数据） | 副本会包含相同关联，这是文件复制的自然结果；首次开启自动同步前集中展示已关联文档数量和目标空间，由用户确认。未确认时只允许查看和手动操作 |
| 同一 Vault 通过 Obsidian Sync / Git 到新设备 | 若插件数据一并同步，按复制场景确认后使用；若未同步，通过「关联已有文档」恢复，不需要为服务端新增设备表 |
| 恢复旧备份 | 先拉取远端版本并三方核对，不能按旧基线直接覆盖 |
| 卸载或清除插件数据 | 本地笔记、云端文档和分享保留；重新安装后需要重新关联已有文档 |

复制 Vault 后的确认是 Vault 级的一次性保护，不逐篇弹窗。若用户将副本当作同一资料库使用，可以保留关联；若作为独立资料库使用，选择「清除副本中的关联」，只删除副本插件数据。产品不尝试通过机器路径猜测用户意图。

本期服务端无需新增关联表或关联接口。服务端改动边界如下：

| 能力 | 是否需要服务端改动 | 说明 |
| --- | --- | --- |
| 保存文档关联 | 否 | 仅存当前 Vault 的插件账本 |
| 多 Vault 关联同一文档 | 否 | 各客户端使用相同远端 ID、独立基线和现有 `If-Match` |
| 首次创建幂等 | 原则上无需 | 服务端已有 `Idempotency-Key` 和回执；验证插件 OAuth 路径可用并接入 |
| 同名冲突 | 否 | 复用路径唯一约束和 `ASSET_PATH_CONFLICT` |
| 一致读取正文、哈希、版本 | 需要验证，必要时调整接口 | 三项必须属于同一内容快照 |
| 侧边自动登录 | 需要 | 身份服务增加短时一次性网页会话衔接能力 |
| 发布与分享语义 | 需要 | 分享设置不得隐式发布最新正文，更新正文需校验目标版本 |

### 9.3 本期不展开

文件夹镜像、批量首次绑定、自动上传全 Vault、自动下载所有云端文档、附件上传、HTML/Canvas 同步、自动文本合并、自动发布、移动端、在线演示专属工作流均不在本期范围。现有网页可用能力仍按权限正常呈现。

本稿不设计旧专用目录到新模型的自动迁移。安装新版不删除或移动任何已有目录和文件；遇到旧目录型配置应停止旧自动任务，提示按新模型重新关联，不能将旧配置静默解释为新规则。本期实现完成后须同步更新旧设计与使用说明，避免两套行为说明并存。
